# lorereef

> 故事設定的 **IDE**:打開一個你自己的設定集資料夾,用卡片 / 心智圖 / 時間線看它、編它,
> 並由**一致性稽核**告訴你哪裡自打嘴巴 —— 死了又出場、能力先用後學、同一天在兩個城市。
>
> lorereef **不保存你的故事**。它只定義設定的**中繼資料格式**(卡片、關聯型別、時效區間),資料永遠在你自己的資料夾 / repo 裡。

**狀態:📋 Spec 階段**(只有規格,尚無實作)。規格見 [`doc/SPEC.md`](doc/SPEC.md)。

---

## 為什麼

AI 讓寫小說變便宜,長篇 / 多線 / 多作者(含 AI 協作)的設定會爆量。爆量之後最先壞掉的不是文筆,是**一致性**。

既有工具(Novelcrafter / Sudowrite Story Bible / Campfire / World Anvil / Aeon Timeline)都在做「幫你寫、幫你查」,
**沒有一個真的在做一致性稽核**,而且多半把你的設定鎖在它們的雲端。lorereef 反過來:

| | 既有工具 | lorereef |
|---|---|---|
| 資料在哪 | 它們的雲端 / 專有格式 | **你的資料夾**,markdown + YAML,git 友善 |
| 一致性 | 靠你自己記 | **規則引擎**確定性抓硬矛盾 + **LLM** 抓軟矛盾 |
| AI 協作 | 內建、鎖定供應商 | 開放:agent 讀寫同一批 markdown,IDE 只是其中一個 client |
| 形式 | 雲端 SaaS | **本機 IDE**(像程式編輯器之於程式碼) |

## 三層,只擁有前兩層半

```
┌─────────────────────────────────────────────┐
│  IDE(本 repo)                              │  卡片 grid · 心智圖 · 時間線 · 稽核面板
├─────────────────────────────────────────────┤
│  引擎(本 repo)                             │  schema 驗證 · 規則引擎 · LLM 軟稽核
├─────────────────────────────────────────────┤
│  中繼資料格式(本 repo 定義)                │  卡片 frontmatter · world.yaml · 關聯型別
├─────────────────────────────────────────────┤
│  你的設定集(不在本 repo)                   │  cards/**/*.md —— 你的資料夾、你的 git
└─────────────────────────────────────────────┘
```

本 repo 只放 `examples/` 一個極小的虛構範例世界,用來跑測試和 demo。

## 稽核分兩層

| 矛盾類型 | 例子 | 誰抓 | 可靠度 |
|---|---|---|---|
| **硬矛盾** | 死了又出場、時間線倒錯、地點衝突、能力先用後學 | **規則引擎**(確定性) | 抓到就是真的;寧可漏不誤報 |
| **軟矛盾** | 動機不一致、語氣走鐘、性格前後不符 | **LLM**(`claude -p`) | 建議性質,人裁決 |

硬矛盾能確定性地抓,是因為格式逼你把兩件事寫清楚:**關聯有型別**(父子 / 師徒 / 擁有 / 位於)、**事實有時效區間**(t1~t2 存活、t3 之後才會 X)。
**這個格式 + 混合稽核是本體**;卡片 UI 是它的視窗。

## 介面草圖(目標)

- **Card grid** —— 依類型 / 標籤 / 屬性篩選排序的卡片牆;點開即編 frontmatter + body
- **Mind-map** —— 卡片為節點、帶型別關聯為邊;可拖拉、可依時間點篩選「此刻的世界」
- **Timeline** —— 事件錨點 + 每張卡的事實區間橫條;矛盾直接標在時間線上
- **Audit panel** —— 硬矛盾清單(點一條跳到涉及的兩張卡)+ 軟矛盾建議 + 盲區提示
- **Agent** —— 從 IDE 召喚 `claude -p`,agent 讀寫的是同一批 markdown,改動以 diff 呈現、人核准才落地

## 用法草圖(目標)

```bash
lorereef open ./my-world          # 開 IDE
lorereef validate ./my-world      # CLI:schema、FK、id 唯一
lorereef audit ./my-world         # CLI:硬矛盾,exit 1 = 有矛盾(可進 pre-commit)
lorereef audit ./my-world --soft  # 追加 LLM 軟矛盾建議
```

## 設計原則

1. **不擁有資料** —— 設定集是使用者的資料夾;lorereef 讀寫 markdown,不建 DB、不上雲、不做帳號。
2. **Deterministic-first** —— 能用規則抓的矛盾不問 LLM;LLM 只碰規則抓不到的。
3. **schema 守門** —— 關聯型別、時效區間是**必填結構**,不是自由文字;寫不清楚就 validate 不過。
4. **稽核可解釋** —— 每條矛盾指出哪兩張卡、哪兩個事實、哪條規則;不出「AI 覺得怪怪的」。
5. **IDE 是 client 不是主人** —— CLI 與 IDE 共用同一顆引擎;沒有 IDE 也能在終端機跑稽核。

## 非目標

- 不保存故事資料、不做雲端同步、不做帳號 / 多人即時協作
- 不做寫作輔助(續寫、潤稿)
- 不做出版 / 匯出排版
